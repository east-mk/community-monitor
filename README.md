# 커뮤니티 키워드 감시 봇

**특정 키워드 관련 커뮤니티 게시글 및 구글 뉴스 자동 모니터링 봇**

10분마다 자동으로 실행되어, 설정한 특정 키워드가 들어간 글을 찾아 구글 시트에 기록합니다.

- **커뮤니티 모니터링** 탭: 디시, 뽐뿌, 더쿠, 인스티즈 등 커뮤니티 게시판의 새 글을 제목과 본문까지 검사
  `발견시각 | 커뮤니티 | 게시판 | 제목(링크) | 키워드 | 일치위치 | 링크`
- **구글 모니터링** 탭: 구글 뉴스 검색 결과 중 제목에 키워드가 있는 기사
  `발견시각 | 작성시각 | 사이트 | 분류 | 제목(링크) | 키워드 | 링크`

**기능**
- 10분 주기 자동 수집 (GitHub Actions)
- 커뮤니티는 제목 + 본문, 검색 결과는 제목만 검사
- 같은 링크는 시트에 한 번만 기록
- 1행 필터로 사이트/분류/게시판별로 골라 보기

## 파일 구성

| 파일 | 역할 |
|---|---|
| `monitor.py` | 본체. 수집 → 제목/본문 키워드 매칭 → 중복 제거 → 시트 기록 |
| `search_sources.py` | 구글 뉴스 검색 수집 (구글 모니터링 탭). 네이버·다음 코드도 들어 있으나 꺼져 있음 |
| `sites.py` | 사이트/게시판 URL, 게시글 링크 패턴, 본문 위치(CSS 선택자) 설정 |
| `keywords.txt` | 감시 키워드 (한 줄에 하나) |
| `requirements.txt` | 필요한 파이썬 패키지 |
| `.github/workflows/monitor.yml` | GitHub Actions 무료 자동 실행(10분 간격) |

## 1단계. 구글 시트 + 서비스 계정 만들기 (무료, 1회)

1. [구글 시트](https://sheets.google.com)에서 빈 시트를 하나 만듭니다.
   주소가 `https://docs.google.com/spreadsheets/d/<이 부분>/edit` 이면 `<이 부분>`이 **SHEET_ID** 입니다.
2. [Google Cloud Console](https://console.cloud.google.com)에서 새 프로젝트를 만듭니다.
3. 메뉴 `API 및 서비스 → 라이브러리`에서 **Google Sheets API**를 검색해 "사용"을 누릅니다.
4. `API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → 서비스 계정`으로 계정을 만듭니다.
5. 만든 서비스 계정을 열고 `키 → 키 추가 → 새 키 만들기 → JSON`으로 키 파일을 내려받습니다.
6. JSON 안의 `client_email` 값(…@…iam.gserviceaccount.com)을 복사해서,
   1번에서 만든 구글 시트의 **공유**에 **편집자** 권한으로 추가합니다.

## 2단계. 실행 방법 (둘 중 하나)

### 방법 A. GitHub Actions (PC를 켜둘 필요 없음, 추천)

1. GitHub에서 새 저장소(Public 추천)를 만들고 파일을 올립니다.
   `.github` 폴더는 숨김 폴더라 끌어다 놓으면 빠지기 쉬우니, `Add file → Create new file`에서
   이름을 `.github/workflows/monitor.yml`로 입력하고 내용을 붙여넣는 쪽이 안전합니다.
2. 저장소 `Settings → Secrets and variables → Actions → New repository secret`에서 2개를 등록합니다.
   - `SHEET_ID` : 시트 ID
   - `GOOGLE_CREDENTIALS` : 내려받은 JSON 파일의 **내용 전체**
3. `Actions` 탭에서 `community-monitor`를 열고 `Run workflow`로 한 번 수동 실행해 봅니다.
4. 이후 10분마다 자동 실행됩니다.

참고
- GitHub의 예약 실행은 몇 분씩 늦어질 수 있어서 "완전 실시간"은 아니고 10~15분 단위입니다.
- 공개 저장소는 Actions가 무료입니다. 비공개 저장소는 월 2,000분 한도가 있어 10분 간격으로는 모자랍니다.
- 공개 저장소는 `keywords.txt`가 남에게 보입니다. Secrets(시트 ID, 서비스 계정 키)는 보이지 않습니다.
- 공개 저장소는 60일간 활동이 없으면 GitHub가 예약 실행을 멈춥니다. 그땐 Actions 탭에서 다시 켜세요.
- 이미 확인한 글 목록(`seen.json`)은 Actions 캐시에 저장됩니다. 캐시는 7일간 쓰이지 않으면 사라지는데,
  그러면 봇이 최근 글을 다시 검사하지만 시트에는 같은 링크가 중복으로 들어가지 않습니다.

### 방법 B. 내 PC/서버에서 상시 실행 (더 짧은 간격 가능)

```bash
pip install -r requirements.txt
export SHEET_ID="시트ID"
export GOOGLE_CREDENTIALS_FILE="/경로/서비스계정키.json"
python monitor.py --loop 300     # 5분마다 반복
```

Windows PowerShell에서는 `export` 대신 `$env:SHEET_ID="시트ID"` 형식을 씁니다.
확인한 글 목록은 같은 폴더의 `seen.json`에 저장됩니다.


## 3단계. 처음 한 번은 반드시 점검 모드로

```bash
python monitor.py --test
```

시트와 `seen.json`을 건드리지 않고, 사이트마다 사이트당 본문 3개만 열어 상태를 보여줍니다.

- `[OK] ... 글 N개` : 목록 수집 정상
- `[글 0개 ...]` : URL이나 `sites.py`의 `pattern`이 안 맞거나, 봇 차단입니다.
- `[실패] ...` : 접속 오류(403 차단, 타임아웃 등)
- `본문 N자, 선택자 OK` : 본문 위치를 정확히 찾음
- `선택자 미적용(일반 추출)` : `body` 선택자가 안 맞아 페이지 전체에서 추정함 → 오탐 가능, 선택자 수정 필요
- `본문 열기 실패` : 글 페이지 접속이 막힘

`sites.py`의 URL/패턴/선택자는 **추정값**이라서 일부 사이트는 위 점검 후 손봐야 합니다.

## 키워드와 검사 방식

`keywords.txt`에 한 줄에 하나씩 적습니다. 대소문자와 공백 개수는 구분하지 않고 **그대로 포함**되면 일치로 봅니다.

1. 제목에 키워드가 있으면 `일치위치`가 `제목`으로 기록됩니다.
2. 제목에 없으면 글 본문 페이지를 열어 본문을 검사합니다. 일치하면 `본문`으로 기록됩니다.
   본문 위치를 못 찾아 페이지 전체에서 추정한 경우는 `본문(불확실)`로 기록됩니다.
3. 한 번 확인한 글은 다시 열지 않습니다. 새로 올라온 글만 열어보기 때문에 처음 몇 번의 실행 뒤에는 빨라집니다.

본문 검사는 글마다 페이지를 한 번씩 더 열기 때문에 차단당할 위험이 커집니다.
사이트당 한 번 실행에 최대 60개(`MAX_BODY_PER_SITE`), 전체 7분(`TIME_BUDGET`)까지만 열고,
남은 글은 다음 실행으로 넘깁니다. 글이 아주 빨리 올라오는 게시판은 일부를 놓칠 수 있습니다.

`기프티엘 유출`처럼 여러 단어 키워드는 그 구절이 그대로 있어야 일치합니다.
`기프티엘` 같은 짧은 키워드를 넣으면 본문 검사에서 일치하는 글이 많아집니다.

## 구글 모니터링 (구글 뉴스)

`keywords.txt`의 키워드를 하나씩 구글 뉴스 RSS로 검색해서, **제목에 키워드가 있는 기사만** 기록합니다.
키가 필요 없고 작성시각도 함께 기록됩니다. 기사 본문은 열지 않습니다.

- 구글 뉴스 링크는 `news.google.com`을 거쳐 원문으로 이동하는 주소입니다.
- 처음 실행하면 며칠 전 기사까지 한꺼번에 들어올 수 있습니다. 작성시각으로 구분하세요.
- 구글 일반 웹 검색은 프로그램 접속을 막아서 뉴스만 수집합니다.

**네이버·다음을 나중에 켜려면**
`search_sources.py`의 `ENABLED_SITES = {"구글"}`에 `"네이버"`, `"다음"`을 추가합니다.
키 없이도 검색 페이지에서 추정해서 가져오지만 막힐 수 있고, 안정적으로 쓰려면 키가 필요합니다.
- 네이버: 2026년 7월 31일부터 네이버 클라우드의 NAVER API HUB에서만 검색 API 키 발급
  (콘솔 `Services → Application Service → NAVER API HUB`에서 앱 등록, 검색 - 뉴스/블로그/카페글 선택)
  → GitHub Secrets `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`
- 다음: [카카오 개발자](https://developers.kakao.com/console/app)에서 앱 생성 → `앱 → 플랫폼 키`의 REST API 키
  → GitHub Secrets `KAKAO_REST_KEY`
- 키를 쓰면 `monitor.yml`의 `env:`에 `NAVER_CLIENT_ID: ${{ secrets.NAVER_CLIENT_ID }}` 형식으로 줄을 추가해야 합니다.

## 제외된 사이트

| 사이트 | 이유 |
|---|---|
| X(트위터) | 무료로 안정적인 수집 방법이 없음 (공식 API 유료, 비공식 우회는 차단/약관 문제) |
| 블라인드 | 앱/로그인 중심이라 공개 목록 수집이 사실상 불가 |
| 에브리타임 | 학교 인증 로그인 필요 |
| 해연갤 | 갤러리 ID를 몰라 비활성. `sites.py`에서 ID를 넣고 `enabled`를 지우면 활성화 |

## 한계와 주의

- 사이트가 개편되면 `pattern`과 `body`를 고쳐야 합니다.
- 더쿠, 에펨코리아, 인스티즈 등 봇 차단이 있는 곳은 GitHub Actions 서버 IP에서 막힐 가능성이 높습니다.
  이 경우 방법 B(집/개인 서버)가 더 잘 통하는 편입니다.
- 게시판 목록의 앞쪽 글만 보기 때문에, 실행 간격 사이에 목록 뒤로 밀려난 글은 놓칠 수 있습니다.
- 로그인해야 볼 수 있는 글이나 JS로 본문을 그리는 페이지는 본문 검사가 안 됩니다.
- 각 사이트의 이용약관/robots.txt를 확인하고, 개인용으로 낮은 빈도로만 쓰세요.
- 서비스 계정 JSON 키는 비밀번호와 같습니다. 코드에 직접 넣거나 공개하지 마세요.
